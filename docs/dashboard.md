# Security Dashboard

The ez-appsec security dashboard is a static web application hosted on GitHub Pages or GitLab Pages. It aggregates vulnerability scan results from one or more repositories into a single view with filtering, drill-down, and AI-powered remediation guidance.

- **GitHub dashboard**: `https://OWNER.github.io/ez-appsec-dashboard/`
- **GitLab dashboard**: `https://GROUP.gitlab.io/ez-appsec-dashboard/`

---

## Setup

### GitHub

```
/ez-appsec install-dashboard [owner/repo]
```

See the [GitHub setup guide](github.md#step-2--set-up-the-dashboard) for full details.

### GitLab

```
/ez-appsec install-dashboard your-group/subgroup
```

See the [GitLab setup guide](gitlab.md#step-1--set-up-the-dashboard) for full details.

---

## Overview

The dashboard header shows total vulnerability counts broken down by severity, an average finding-age metric, and a severity distribution chart. A **Run Scan** button links directly to the latest CI/CD workflow run.

![Dashboard overview showing severity stat cards and distribution chart](screenshots/dashboard-overview.png)

## Multi-project sidebar

When scan results from more than one repository have been pushed, a project sidebar appears on the left. Click any project to filter the main view to that repo's findings only, or select **All Projects** to see the aggregate.

![Multi-project sidebar with project list](screenshots/dashboard-multi-project.png)

---

## Vulnerability list

Findings are displayed as cards sorted by severity (critical first). Each card shows:

- Severity badge (color-coded)
- Finding title and scanner source (gitleaks, semgrep, kics, grype)
- Affected file and line number
- Short description

The list is paginated (100 per page) and updates live as filters change.

![Vulnerability list with severity badges and scanner tags](screenshots/dashboard-vuln-list.png)

---

## Filters

Three filter controls narrow the vulnerability list without a page reload:

| Filter | Options |
|--------|---------|
| **Severity** | All · Critical · High · Medium · Low · Info |
| **Scanner** | All · Gitleaks · Semgrep · Grype · KICS |
| **Search** | Free-text across title, description, and file path |

![Filter bar with severity dropdown, scanner dropdown, and search box](screenshots/dashboard-filters.png)

---

## Finding detail

Click any vulnerability card to open a detail panel with the full finding:

- Rule ID and scanner name
- Severity level
- Affected file path and line number
- Full description
- CVE reference (where available)

![Finding detail panel showing full vulnerability information](screenshots/dashboard-finding-detail.png)

---

## AI remediation guidance

Each finding includes an **AI Fix** panel with:

- Plain-language explanation of the risk
- Step-by-step fix instructions
- Code example where applicable

Requires `OPENAI_API_KEY` to be set in the scanning environment when the scan runs. The guidance is embedded in `vulnerabilities.json` at scan time and displayed statically — no API calls from the browser.

![AI remediation panel with step-by-step fix instructions](screenshots/dashboard-ai-remediation.png)

## GitHub Security tab

When the GitHub scan workflow runs, findings are also uploaded to the repository's **Security → Code scanning** tab as a SARIF report. No additional configuration required.

![GitHub Security tab showing ez-appsec findings](screenshots/github-security-tab.png)

---

## Pull request comments

On pull requests, the workflow posts a findings summary comment with severity counts and a link to the full run. The comment is updated (not duplicated) on each new push to the PR branch.

![Pull request comment showing security scan findings count](screenshots/github-pr-comment.png)

## Updating dashboard assets

When a new ez-appsec release ships:

```
/ez-appsec update-dashboard [owner/repo]
```

This re-provisions App secrets and triggers the `update-assets.yml` workflow to pull the latest `index.html`, `app-github.js`, and `style.css` from the new release.

---

## Data layout

The dashboard reads from the following files in the dashboard repo:

```
data/
  index.json                         # Project registry (auto-generated)
  config.json                        # Dashboard metadata (ez_appsec_version)
  vulnerabilities/
    repo-name.json                   # Per-repo findings
    team/repo-name.json              # Optional team grouping (EZ_APPSEC_TEAM)
```

`index.json` is regenerated by `aggregate-index.py` each time a scan result is pushed. The dashboard JS reads `index.json` on load, then fetches each project's `vulnerabilities.json` on demand.
